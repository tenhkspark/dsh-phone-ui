# スマホでDSH — DSHのWeb UIに足すスマホ専用の層

DSH（DeepSeek Harness）のWeb UIは、デスクトップのウィンドウ幅を前提に作られていて、
画面幅に反応する仕組みが入っていません。このリポジトリは、デスクトップ用の入口の**隣に**
スマホ用の入口を1つ足すものです。中身は小さなリバースプロキシで、配信するHTMLに
狭い画面用のCSSとJSを差し込みます。デスクトップ用の入口・DSH本体・データには手を入れません。

フォークではありません。依存ゼロのNodeスクリプト1本、CSS1枚、JS1本、そして
「常駐させる方法」と「プライベートネットワークから見せる方法」だけです。

```
スマホ ──HTTPS──▶ プライベート網のプロキシ（tailscale serve など :8450）
                        │
                        ▼
                 dsh-phone ゲートウェイ（このリポジトリ・127.0.0.1:8450）
                   ├── /m              → 302 で /?token=<現在のDSHトークン>
                   ├── /__dshm/*.css   → スマホ用スタイル
                   ├── /__dshm/*.js    → スマホ用スクリプト
                   ├── /__dshm/status  → 稼働確認のJSON
                   └── それ以外        → 127.0.0.1:3080（DSH web）
デスクトップ ──HTTPS──▶ 元の入口（例 :8446）— 変更なし
```

## なぜパッチではなく入口を足すのか

配布されているフロントエンド（`@deepseek-ai/dsh` 0.2.1-rc.2、
`dist/assets/index-*.css`）で実測した値です。

- 画面幅によるメディアクエリは**0件**（`@media` は `prefers-reduced-motion` のみ）。
  バンドル内に `matchMedia` の呼び出しも無く、幅でレイアウトが変わる箇所はありません
- 幅440pxの画面では、左レールが**56px**を常に占有。サイドバーを開くとグリッドは
  `280px | 160px` になり、会話本文に残るのは**160px**
- 入力欄のチップは高さ**28px**、入力欄の文字は**14px**。iOSは16px未満の入力に
  フォーカスすると自動でズームするため、そのまま使うと拡大されてしまう
- ノッチやホームインジケータを避ける指定（`viewport-fit=cover`）が無い

バンドルを直接書き換える方法は、次の`npm update`までしか持ちません。リクエスト時に
差し込むプロキシなら、DSHのインストールを触らずに済み、外すのも簡単です。ただし
将来も安泰という意味ではありません。セレクタはDSHの`data-slot`名に依存しているので、
後のビルドで名前が変わればスキンは効かなくなります（下の「これはやらないこと」参照）。

## 追加されるもの

- 左レールがスライドオーバーになり、浮かせたメニューボタン1個で開閉できる
- 入力欄・ヘッダ・メッセージ下の操作アイコンが36〜40pxのタップ領域になる
- 入力欄が16pxになり、iOSのフォーカス時ズームが止まる
- アプリの高さを*見えている範囲*に合わせるので、キーボードが出ても入力欄が隠れない
  （`visualViewport`）
- 全画面（PWA）向けのセーフエリア余白、ホーム画面アイコンとmanifestの経路
- 固定の入口URL（`/m`）が現在のトークンへ解決するので、DSH再起動でトークンが
  変わってもホーム画面のショートカットが切れない
- 長いコードブロックや表は、ページをはみ出さず横スクロールになる

## 必要なもの

- DSH webがHTTPで動いていること（既定 `http://127.0.0.1:3080`）
- 同じホストにNode.js 20以降（npmパッケージは不要）
- 最近のスマホのブラウザ。切り替え幅（ブレイクポイント）は自分で設定します。
  検証したのは1クラスの端末だけです（下の制限を参照）
- 任意: スマホから届かせるためのプライベートネットワーク（例ではTailscale）。インターネットへ
  ポートを開ける必要はありません

## 導入

1. `scripts/` をDSHが動いているホストへコピーする（例: `~/dsh-phone`）。

2. 起動する（トークンのログのパスは、DSHが起動URLを書いているファイルに置き換え）:

   ```sh
   PORT=8450 \
   UPSTREAM=http://127.0.0.1:3080 \
   TOKEN_LOG="$HOME/.dsh/dsh-launchd.log" \
   node ~/dsh-phone/server.mjs
   ```

   `TRUSTED_HOST` は任意で、通常は不要です。DSHを `--trusted-host <host:port>` で
   起動している場合だけ、同じ値を渡します（例: `TRUSTED_HOST=myhost.example.ts.net:8446`）。
   そのときゲートウェイは `Host`/`Origin` をその値にして転送するので、別ポート経由の
   リクエストがDSHのオリジン検査を通ります。指定しなければヘッダはそのまま転送されます。

3. ローカルで確認する:

   ```sh
   curl -s http://127.0.0.1:8450/__dshm/status
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8450/m   # 302 が返る
   ```

4. 常駐させる。`deploy/com.example.dsh-phone.plist`（macOS launchd）と
   `deploy/dsh-phone.service`（Linux systemd）がテンプレートです。パスとポートを埋めて、
   コメントに書いた手順で読み込みます。

5. スマホから届くようにする（プライベート網のみ）。Tailscaleの場合:

   ```sh
   tailscale serve --bg --https=8450 http://127.0.0.1:8450
   ```

   **tailnetのACLでポートを列挙している場合、そのリストに新しいポートを足してください。**
   書いていないポートは黙って落とされます。手元では動いているのにスマホだけ
   「接続できません」になる原因は、ほぼこれです。

6. スマホで `https://<your-host>:8450/m` を開き、ブラウザの「ホーム画面に追加」を使う。
   トークンを直書きしたURLは再起動で切れますが、`/m` は切れません。

   任意: 自分の `apple-touch-icon-180.png`、`icon-192.png`、`icon-512.png` を
   `scripts/icons/` に置くとホーム画面のアイコンになります（アイコンとmanifestの行は、
   ファイルがある時だけHTMLに差し込まれます）。DSHのロゴを自分のアプリの
   アイコンとして同梱しないでください（DeepSeekの資産です）。自分の画像か、無地にしましょう。

## 自分のスマホに合わせる

ブレイクポイントは1つの数値で、2つのファイルに同じ値が入っています（`mobile.js` の
`MAX_W`、`mobile.css` の `@media (max-width: 520px)`）。既定の520pxは、
Pro Max級の実測幅440pxより上に置いた値です。判定は幅だけなので、デスクトップの窓を
520px未満まで縮めれば同じように効きます。

自分の端末の幅を測るには、スマホでページを開き、次の行をブックマークとして保存して
ブックマーク一覧から実行するか、リモートインスペクタのコンソールで実行します:

```js
javascript:prompt('', innerWidth + 'x' + innerHeight)
```

測った幅より少し上を `MAX_W` にして、2つのファイルを揃えます。新しい端末で確認したい点:

- キーボードが出たときに入力欄が隠れないか（`visualViewport` が動く必要あり）
- サイドバーと幕のサイズが適切か（`min(320px, 86vw)`）
- 全画面モードのセーフエリア余白が、縦横どちらでも正しいか
- 40pxのタップ領域が自分の指に合っているか（もっと大きくしたい場合がある）

## これはやらないこと

- 認証は追加しません。DSH自身のトークン/Cookieに依存します。ポートはプライベート網の
  内側かトンネルの後ろに置いてください。インターネットには公開しないでください。
- 幅の広い窓の見た目は変えません。すべての規則は幅のクエリの中にあり、しかも
  `html.dshm`（スクリプトがブレイクポイント以下のときだけ付ける）で限定しています。
- DSHのフォークではありません。セレクタは意図的に `data-slot` 属性名を使っています
  （CSSモジュールのクラス名はビルドごとにハッシュが変わるため）。それでもDSHの更新で
  スロット名が変われば効かなくなります。そのときは実機で
  `document.querySelectorAll('[data-slot]')` を実行してセレクタを作り直すのが最短です。
- 検証は1つのホストと1クラスの端末でしかしていません。特にキーボードの挙動は端末依存です。
  自分の端末で確認してください。

## 困ったとき

- **スマホから繋がらないが、ホスト上では動く。** ACL/ファイアウォールでポートが許可されて
  いないか、スマホがプライベート網に入っていません。ゲートウェイのログに端末の
  user-agent付きの `hit` 行が出ているかを見てください。
- **`/m` が503を返す。** `TOKEN_LOG` からトークンを読めていません。DSHが起動URLを
  書いているファイルを指定してください。
- **ページは出るがスキンが効かない。** `html.dshm` が付いていません。幅が `MAX_W` を
  超えているか、スクリプトがブロックされています。`innerWidth` とコンソールを確認。
- **右上のヘッダのアイコンが切れて見える。** その行にクリップがかかっています。標準の
  レイアウトでは、メニューボタンのために足した左のパディングがアイコンを
  行の外へ押し出します。`overflow: hidden` を付けないでください。
- **サイドバーは開くが後ろが暗くならない。** 幕は `document.body` に挿入しています。
  インラインスタイルを禁じるCSPがあると表示されません。

## 元に戻す

```sh
launchctl bootout gui/$(id -u)/com.example.dsh-phone   # または systemctl --user disable --now dsh-phone
tailscale serve --https=8450 off
rm -rf ~/dsh-phone
```

DSH側には何も書き込んでいないので、戻す作業はありません。
