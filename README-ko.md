# 휴대폰에서의 DSH — DSH 웹 UI를 위한 휴대폰 전용 레이어

DSH(DeepSeek Harness)는 데스크톱 창을 기준으로 만든 웹 UI를 제공합니다. 휴대폰 너비 화면에서도 사용할 수는 있지만 공간이 비좁고, 프런트엔드 어디에서도 화면 너비에 반응하지 않습니다. 이 저장소는 데스크톱 진입점 **옆에** 휴대폰 진입점을 추가합니다. 제공하는 페이지에 좁은 화면용 스타일시트와 스크립트를 주입하는 작은 리버스 프록시입니다. 데스크톱 진입점, DSH 설치 및 데이터는 그대로 둡니다.

여기에 포크는 없습니다. 의존성이 없는 Node 스크립트 하나, 스타일시트 하나, 스크립트 하나와 이를 계속 실행하고 비공개로 노출하는 방법이 전부입니다.

```
휴대폰 ──HTTPS──▶ 사설망 프록시 (tailscale serve 등 :8450)
                        │
                        ▼
                 dsh-phone 게이트웨이 (이 저장소, 127.0.0.1:8450)
                   ├── /m              → 302 → / (게이트웨이가 대신 로그인)
                   ├── /__dshm/*.css   → 휴대폰용 스타일시트
                   ├── /__dshm/*.js    → 휴대폰용 스크립트
                   └── 그 외 경로      → 127.0.0.1:3080 (DSH 웹)
데스크톱 ──HTTPS──▶ 원래 DSH 진입점 (:8446) — 변경 없음
```

## 패치 대신 두 번째 진입점을 두는 이유

제공되는 프런트엔드(`@deepseek-ai/dsh` 0.2.1-rc.2,
`dist/assets/index-*.css`)에서 측정한 값입니다.

- 너비 기반 미디어 쿼리: **0** (유일한 `@media` 규칙은 `prefers-reduced-motion`),
  번들에는 `matchMedia` 호출도 없음 — 레이아웃은 너비에 따라 바뀌지 않음
- 440px 뷰포트에서 왼쪽 레일은 **56px**을 항상 유지합니다. 사이드바를 열면
  그리드가 `280px | 160px`로 바뀌어 대화 영역에는 **160px**만 남습니다.
- 컴포저 칩은 높이가 **28px**이고 편집 영역은 **14px**이라, 포커스 시 iOS가
  페이지를 확대합니다(16px 미만은 확대함).
- 노치/홈 인디케이터 안전 영역을 처리하는 지정이 없습니다(`viewport-fit=cover`).

번들 자산을 패치하는 방법은 다음 `npm update` 전까지만 동작합니다. 요청 시점에
주입하면 DSH 설치를 건드리지 않고 한 단계로 제거할 수 있습니다. 다만 앞으로도 안전하다는
뜻은 아닙니다. 선택자는 DSH의 `data-slot` 이름에 의존하므로, 이후 빌드에서 이름이 바뀌면
스킨이 깨집니다(아래 제한 참조).

## 제공되는 것

- 왼쪽 레일이 하나의 플로팅 메뉴 버튼이 있는 슬라이드 오버 패널이 됩니다
- 컴포저, 헤더, 메시지별 작업의 탭 대상 크기가 36–40px입니다
- 편집 영역이 16px이라 iOS가 포커스 시 확대하지 않습니다
- 앱 크기가 *보이는* 상자에 맞춰지므로 컴포저가 화면 키보드 위에 유지됩니다
  (`visualViewport`)
- 전체 화면/PWA 모드를 위한 안전 영역 패딩과 홈 화면 아이콘/매니페스트 경로
- 대신 로그인해 주는 고정 진입 URL(`/m`) — 게이트웨이가 DSH 세션 쿠키를 보관해 매
  요청에 실어 보내므로, DSH 재시작·토큰 회전·휴대폰 브라우저의 쿠키 유실에도 홈 화면
  바로가기가 계속 동작합니다
- 긴 코드 블록과 표가 페이지를 넘치지 않고 가로로 스크롤됩니다

## 요구 사항

- DSH 웹이 실행 중이고 HTTP 오리진에서 접근 가능해야 합니다(기본값 `http://127.0.0.1:3080`)
- 같은 호스트에 Node.js 20 이상(npm 패키지는 필요 없음)
- 최신 휴대폰 브라우저. 브레이크포인트는 직접 설정합니다. 검증은 한 등급의 기기에서만
  했습니다(아래 제한 참조)
- 선택 사항: 휴대폰이 인터넷에 포트를 열지 않고 호스트에 접근하도록 사설 네트워크
  터널(예제에서는 Tailscale 사용)

## 설치

1. `scripts/`를 DSH를 실행하는 호스트에 복사합니다. 예: `~/dsh-phone`.

2. 실행합니다(토큰 로그 경로를 DSH가 URL을 출력하는 파일로 바꾸십시오):

   ```sh
   PORT=8450 \
   UPSTREAM=http://127.0.0.1:3080 \
   TOKEN_LOG="$HOME/.dsh/dsh-launchd.log" \
   node ~/dsh-phone/server.mjs
   ```

   `TRUSTED_HOST`는 선택 사항이며 보통은 필요하지 않습니다. DSH를
   `--trusted-host <host:port>`로 시작할 때만 같은 값을 넘기십시오(예:
   `TRUSTED_HOST=myhost.example.ts.net:8446`). 그러면 게이트웨이가 `Host`/`Origin`을 그
   값으로 전송하여 두 번째 포트로 들어오는 요청이 DSH의 오리진 검사를 통과합니다.
   지정하지 않으면 헤더는 그대로 전달됩니다.

3. 로컬에서 확인합니다:

   ```sh
   curl -s http://127.0.0.1:8450/__dshm/status
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8450/m   # expect 302
   ```

4. 계속 실행되게 합니다. `deploy/com.example.dsh-phone.plist`(macOS launchd)와
   `deploy/dsh-phone.service`(Linux systemd)는 템플릿입니다. 경로와 포트를 채운 뒤
   주석에 설명된 대로 로드하십시오.

5. 휴대폰에 비공개로 노출합니다. Tailscale 사용 시:

   ```sh
   tailscale serve --bg --https=8450 http://127.0.0.1:8450
   ```

   **tailnet ACL에 허용 포트가 명시되어 있다면 새 포트도 거기에 추가하십시오.**
   목록에 없는 포트는 조용히 드롭됩니다. 로컬에서는 모두 동작하는데 휴대폰에서는
   "연결할 수 없음"이 표시됩니다. 설정이 깨진 것처럼 보이는 가장 흔한 이유입니다.

6. 휴대폰에서 `https://<your-host>:8450/m`를 연 다음 브라우저의
   "홈 화면에 추가"를 사용하십시오. `/m` 진입점은 토큰 회전을 견디며, 브라우저가
   쿠키를 잃거나 낡은 쿠키를 계속 보내도 게이트웨이가 매번 다시 로그인합니다.

   선택 사항: 직접 만든 `apple-touch-icon-180.png`, `icon-192.png`, `icon-512.png`를
   `scripts/icons/`에 넣으십시오(아이콘과 매니페스트 링크는 파일이 있을 때만 주입됩니다). DSH 로고를 자신의 앱 아이콘으로 사용하지 마십시오.
   DeepSeek 소유입니다. 직접 만든 이미지를 사용하거나 아무것도 사용하지 마십시오.

## 휴대폰에 맞게 조정

브레이크포인트는 하나의 숫자이며 두 파일에 모두 있습니다(`mobile.js`의 `MAX_W`,
`mobile.css`의 `@media (max-width: 520px)` 블록)이며, 두 곳을 함께 바꿔야 합니다.
520px은 Pro Max급 440px 뷰포트보다 위에 오도록 고른 값입니다. 판정은 너비만 보므로,
데스크톱 창을 520px 미만으로 줄여도 똑같이 적용됩니다.

자신의 기기를 측정하려면 휴대폰에서 페이지를 열고, 아래 줄을 북마크로 저장해
북마크 목록에서 실행하거나 브라우저의 원격 인스펙터에서 실행하십시오.

```js
javascript:prompt('', innerWidth + 'x' + innerHeight)
```

`MAX_W`를 자신의 너비보다 조금 크게 설정하고(방향/가로 모드가 의도한 대로 계속
일치하도록) 두 파일을 동기화하십시오. 새 기기에서 확인할 만한 항목:

- 키보드가 열릴 때 컴포저가 계속 보이는가(`visualViewport` 필요)
- 사이드바와 스크림 크기가 적절한가(`min(320px, 86vw)`)
- 전체 화면 모드에서 두 방향 모두 안전 영역 패딩이 올바르게 보이는가
- 탭 대상이 엄지로 누르기 편한가, 40px 하한을 더 키워야 하는가

## 이 구성이 하지 않는 일

- 자체 인증은 추가하지 않지만 대신 로그인해 줍니다. 게이트웨이가 DSH 쿠키를
  보관하므로 포트에 닿는 사람은 세션을 얻습니다. 포트를 사설 네트워크에 두거나
  터널 뒤에 두십시오. 인터넷에 노출하지 마십시오.
- 넓은 창의 레이아웃은 바꾸지 않습니다. 모든 규칙은 `html.dshm`으로 제한된 너비
  쿼리 안에 있으며, 스크립트는 브레이크포인트 아래에서만 이 클래스를 추가합니다.
- DSH 포크가 아닙니다. 선택자는 의도적으로 DSH의 `data-slot` 속성 이름을
  사용하지만(CSS 모듈 클래스 이름은 빌드마다 해시됨), DSH 업데이트가 슬롯 이름을
  바꾸어 스킨을 깨뜨릴 수 있습니다. 그럴 때는 라이브 페이지에서
  `document.querySelectorAll('[data-slot]')`를 실행하는 것이 선택자 목록을 다시
  만드는 가장 빠른 방법입니다.
- 하나의 호스트와 하나의 휴대폰 등급에서 작성하고 확인했습니다. 특히 키보드
  처리는 기기에 따라 다릅니다. 자신의 휴대폰에서 확인하십시오.

## 문제 해결

- **휴대폰에서 연결할 수 없고 호스트에서는 로컬로 동작함.** ACL/방화벽에서 포트가
  허용되지 않았거나 휴대폰이 사설 네트워크에 없습니다. 게이트웨이 로그에서 휴대폰
  사용자 에이전트가 있는 `hit` 줄을 확인하십시오.
- **`/m`이 503을 응답함.** 게이트웨이가 `TOKEN_LOG`에서 토큰을 찾지 못했습니다.
  DSH가 시작 URL을 쓰는 파일로 지정하십시오.
- **페이지는 로드되지만 스킨이 아무것도 하지 않음.** `html.dshm`이 추가되지
  않았습니다. 뷰포트가 `MAX_W`보다 넓거나 스크립트가 차단되었습니다. `innerWidth`와
  콘솔을 확인하십시오.
- **오른쪽 헤더 아이콘이 잘린 것처럼 보임.** 해당 행을 무언가가 클리핑하고
  있습니다. 기본 레이아웃에서 메뉴 버튼 자리를 만드는 왼쪽 패딩이 아이콘을 행 밖으로
  밀어냅니다. 여기에 `overflow: hidden`을 추가하지 마십시오.
- **사이드바가 열리지만 뒤 페이지가 어두워지지 않음.** 스크림은
  `document.body`에 삽입됩니다. 인라인 스타일을 차단하는 엄격한 CSP는 이를
  드롭합니다.

## 제거

```sh
launchctl bootout gui/$(id -u)/com.example.dsh-phone   # or: systemctl --user disable --now dsh-phone
tailscale serve --https=8450 off
rm -rf ~/dsh-phone
```

DSH에 기록된 것이 없으므로 되돌릴 것도 없습니다.

## 크레딧

- DeepSeek의 DSH(DeepSeek Harness) — 그대로 사용했으며 수정하지 않았고 모델
  가중치는 관련되지 않습니다. 이 레이어는 `data-slot` 이름과 토큰/URL 동작을 기반으로
  합니다.
- 기여: **tenhkspark**(설계·구현), **DeepSeek V4.1 Flash 1017**(검토 및 번역 확인,
  모두 로컬에서 실행).
